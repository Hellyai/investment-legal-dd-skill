# 完整尽调工作流

## 第一轮资料后

1. 建立虚拟资料索引并分配稳定 `DOC` 编号；
2. 将首轮请求映射为已提供、部分提供、存在冲突、无法提供、公司称不适用或仍缺失；
3. 建立 `FACT`、`ISS` 和 `ACT` 台账；
4. 单独形成一份证据支持的尽调重点及问题分析Word；
5. 交付分析Word并在对话框列示建议补充方向，请客户确认后暂停；
6. 客户确认后，按确认内容单独形成一份差异化补充尽调清单Word。

## 第二轮及后续

沿原编号更新新增证据、剩余缺口、公司解释、风险等级和交易动作。每一轮仍先生成更新后的尽调重点及问题分析Word，待客户确认后再生成该轮补充尽调清单Word。只有关键事实有证据、矛盾已解释、法律影响已判断且处理责任和期限确定时，问题才可关闭。

## 完整报告

1. 锁定范围、集团主体、资料截止日和报告基准日；
2. 按 [report-completeness.md](report-completeness.md) 建立覆盖矩阵并判断资料是否达到正式报告出具门槛；达到门槛或客户明确指令出具完整报告，任一条件满足即进入完整报告模式；
3. 客户未要求完整报告且资料未达到门槛时，继续执行“先问题分析Word、确认后补充清单Word”的补充尽调流程；
4. 进入完整报告模式后，选择 [report-format-profiles.md](report-format-profiles.md) 中适合项目的一种成文格式，完整披露事实、证据限制、法律依据、适用分析、投资影响和处理建议；资料不足不改变正式完整版结构，但须逐项披露受限结论和未决资料；
5. 完成逐主体、逐轮次、逐事项复核和附件勾稽，将主要问题前置，并在附录保留未决资料、证据索引和交易闭环。

完整报告交付后，不自动生成投委会PPT。仅在用户确认需要且选定入选问题后，另行启动 [ic-red-flag-ppt.md](ic-red-flag-ppt.md)。

## 签约与交割更新

只更新基准日后的重大变化、交割条件、整改和新增事项，不机械重做全部报告。

## 停止条件

补充模式第一阶段以问题分析Word交付并请求客户确认为停止点；客户确认后的第二阶段以补充清单Word交付为停止点。完整报告模式以经渲染检查的正式完整版报告Word交付完成为停止点。不得在同一次未明确要求的任务中跨越客户确认节点，也不得自动从补充清单继续扩展到完整报告。
